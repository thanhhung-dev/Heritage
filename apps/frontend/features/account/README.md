# Public account UI (HER-163)

`PublicShell` accepts an optional `account: PublicAccount | null`. An absent account renders Sign In and Sign Up; an account renders notification and account icon buttons without a visible name or chevron beside the Profile trigger. The avatar and identity belong inside the dropdown. HER-162 owns supplying the real session and signing out. `AccountNavigation` exposes `onSignOut` for that integration; Logout is disabled when no handler exists.

The user's subsequent request authorizes Sign In and Sign Up pages from Figma. Guest actions now link to the standalone `/sign-in` and `/sign-up` pages in `config/public-auth.ts`. `AccountNavigation` still accepts an optional `onAuthRequest` callback, which takes precedence over route navigation when supplied. Sign In has local field validation and password visibility; Sign Up follows the social-provider-only reference. These screens do not send authentication requests or fabricate a session. See `features/auth/README.md` for scope and design references.

The user-approved Figma menu contains Account Profile, Help Center, Language, and Logout. Account Profile has no approved destination yet and remains disabled in `PUBLIC_ACCOUNT_LINKS`. Help Center links to `/faq`; Language is disabled until the language-switching feature exists. The existing `/preferences` route is preserved but is no longer listed in this menu. Notifications currently has no handler or data source and remains disabled; no speculative notification panel or sample notifications are added. Footer destinations are nullable in `config/public-footer.ts`; unconfirmed destinations render as text, without dummy links or invented pages. Footer visibility is limited to Home, Map, Library, and FAQ.

The shared public header uses a drawer at phone widths below 768px. Tablets and desktops at 768px and above retain horizontal navigation. The drawer closes on navigation, Escape, or a resize to 768px and above. The existing `/preview` page includes a clearly labeled isolated account example for inspecting both Guest and Profile layouts without creating a fake session in the application.

Design reference: Heritage Figma, Footer `261:1855`. The account dropdown and mobile layouts are extensions authorized by the user. They reuse the installed Ant Design components, project logos, Poppins/Inter, and semantic tokens in `components/ThemeProvider/GlobalStyle/global.ts`. Footer copy and group labels follow Figma; foreground contrast is increased for readability.

Account design references: authenticated header `643:1239` and Profile User `653:2249`, on the User components page `114:2`. Both header glyphs use the original 14px Figma SVGs in 30px glass circles, inside 44px hit areas. The dropdown keeps the reference's 178px width, 186px height, 16px corners, 0.6px border, 53px identity row, 27px dynamic avatar, 25px actions, Inter typography, and translucent background. It is not scaled up. Six exported SVGs are stored locally as `public/figma/account-{bell,user,profile,help,language,logout}.svg`; the fractional menu-icon dimensions are preserved by decorative CSS backgrounds. The reference portrait is not copied into the application: real account data owns the avatar URL.

The root layout places the existing `GlobalProvider` inside `<body>`. This preserves the providers and content while preventing their generated wrapper elements from creating invalid HTML directly inside `<html>` and causing hydration failures.
