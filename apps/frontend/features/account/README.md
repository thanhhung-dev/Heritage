# Public account UI (HER-163 / HER-162)

`PublicAccountProvider` supplies a controlled `account: PublicAccount | null` and optional `onSignOut` callback. Consumers use the provider unless an explicit account prop overrides it. The provider defaults to Guest and does not fetch, persist, or fabricate a session. Logout preserves the supplied callback and restores focus after switching to Guest.

`PublicShell` accepts an optional `account: PublicAccount | null`. An absent account renders Sign In and Sign Up; an account renders notification and account icon buttons without a visible name or chevron beside the Profile trigger. The avatar and identity belong inside the dropdown. HER-162 owns supplying the real session and signing out. `AccountNavigation` exposes `onSignOut` for that integration; Logout is disabled when no handler exists.

Sign In and Sign Up forms, validation, routes, configuration, palette and assets have moved to Story HER-170 (`story/HER-170-login-and-register-in-heritages`), created from develop. HER-119 retains the Guest button styling, account dropdown and public shell. `AccountNavigation` keeps its optional `onAuthRequest` callback; Guest buttons do not navigate to missing auth pages on this branch. After both Stories are integrated, wire the fallback destinations using HER-170's `PUBLIC_AUTH_ROUTES`. No authentication requests or fake sessions are added by HER-119.

The user-approved Figma menu contains Account Profile, Help Center, Language, and Logout. Account Profile has no approved destination yet and remains disabled in `PUBLIC_ACCOUNT_LINKS`. Help Center links to `/faq`; Language is disabled until the language-switching feature exists. The existing `/preferences` route is preserved but is no longer listed in this menu. Notifications currently has no handler or data source and remains disabled; no speculative notification panel or sample notifications are added. Footer destinations are nullable in `config/public-footer.ts`; unconfirmed destinations render as text, without dummy links or invented pages. Footer visibility is limited to Home, Map, Library, and FAQ.

The shared public header uses a drawer at phone widths below 768px. Tablets and desktops at 768px and above retain horizontal navigation. The drawer closes on navigation, Escape, or a resize to 768px and above. Each header has a unique drawer ID, including preview instances. The authenticated header displays the Figma notification and account icons in 30px glass circles inside 44px hit areas. Notifications remain disabled until a notification feature is available. The account name is part of the trigger's accessible name and is displayed with an optional email and supplied avatar inside the dropdown; long identity text is truncated with a title containing its full value.

An open account dropdown closes when crossing the 768px breakpoint in either direction. The header restores focus to the account trigger in the newly visible layout via scoped button refs. Standalone account examples restore focus to their own trigger. The breakpoint listener exists only while the dropdown is open and is removed on close or unmount.

The existing `/preview` page nests an isolated controlled provider. Guest, Profile, and long-name controls update both the real `PublicHeaderControls` example and the standalone `AccountNavigation` example. Sample sign-out returns both to Guest, with focus restored to the Login button or mobile menu trigger. These sample state changes never affect the outer public header, write browser storage, or make authentication requests.

Account design references: authenticated header `643:1239` and Profile User `653:2249`, on the User components page `114:2`. Both header glyphs use the original 14px Figma SVGs in 30px glass circles, inside 44px hit areas. The dropdown keeps the reference's 178px width, 186px height, 16px corners, 0.6px border, 53px identity row, 27px dynamic avatar, 25px actions, Inter typography, and translucent background. It is not scaled up. Mobile action rows remain at least 44px high and the card grows to fit them. Six exported SVGs are stored locally as `public/figma/account-{bell,user,profile,help,language,logout}.svg`; the fractional menu-icon dimensions are preserved by decorative CSS backgrounds. The reference portrait is not copied into the application: real account data owns the avatar URL.

The root layout places the existing `GlobalProvider` inside `<body>`. This preserves the providers and content while preventing their generated wrapper elements from creating invalid HTML directly inside `<html>` and causing hydration failures.
