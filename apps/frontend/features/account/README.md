# Public account UI (HER-163 / HER-162)

`PublicAccountProvider` supplies a controlled `account: PublicAccount | null` and optional `onSignOut` callback to the public layout. `usePublicAccount` exposes the account, derived Guest/Authenticated status, and callback to header consumers. The provider defaults to Guest and does not fetch, persist, or fabricate a session. A future backend session adapter must supply the account and update it after sign-out; this presentation state is not authorization.

`PublicShell`, `PublicHeaderControls`, and `AccountNavigation` retain their optional account props. An explicit account (including null) overrides the provider. An explicit account uses its own sign-out callback rather than signing out an unrelated provider account. Without an explicit account, the header consumes the shared provider. Sign-out remains disabled when no handler exists.

Login and registration are buttons only, as requested by the user. No account forms, modal, validation, or authentication requests are implemented. `AccountNavigation` accepts an optional `onAuthRequest` callback for future integration; the shared header and preview do not supply a handler yet.

The user approved replacing the old account menu with the current Figma menu: Account Profile, Help Center, Language, and Logout. Account Profile has no approved destination yet and remains disabled in `PUBLIC_ACCOUNT_LINKS`. Help Center links to the existing FAQ route. Language is disabled until a real language-switching integration exists. The existing `/preferences` route remains available but is no longer listed in this menu. Logout still calls the supplied session callback. Footer destinations are nullable in `config/public-footer.ts`; unconfirmed destinations render as text, without dummy links or invented pages. Footer visibility is limited to Home, Map, Library, and FAQ.

The shared public header uses a drawer at phone widths below 768px. Tablets and desktops at 768px and above retain horizontal navigation. The drawer closes on navigation, Escape, or a resize to 768px and above. Each header has a unique drawer ID, including preview instances. The authenticated header displays the Figma notification and account icons in 30px glass circles inside 44px hit areas. Notifications remain disabled until a notification feature is available. The account name is part of the trigger's accessible name and is displayed with an optional email and supplied avatar inside the dropdown; long identity text wraps without overflowing.

An open account dropdown closes when crossing the 768px breakpoint in either direction. The header restores focus to the account trigger in the newly visible layout via scoped button refs. Standalone account examples restore focus to their own trigger. The breakpoint listener exists only while the dropdown is open and is removed on close or unmount.

The existing `/preview` page nests an isolated controlled provider. Guest, Profile, and long-name controls update both the real `PublicHeaderControls` example and the standalone `AccountNavigation` example. Sample sign-out returns both to Guest, with focus restored to the Login button or mobile menu trigger. These sample state changes never affect the outer public header, write browser storage, or make authentication requests.

Current design references: Heritage Figma authenticated header `643:1239` and Profile User `653:2249` on the User components page `114:2`. These replace the earlier Joblin dropdown reference `427:2065`. The profile card keeps the glass surface, rounded border, identity row, action icons, and session divider from Figma. The 178px-wide reference is displayed at 1.5x scale for readable identity and action text; rows have at least 44px height on mobile. Notification/account SVGs render at their original 14px size. Menu SVGs retain their intrinsic dimensions (including fractional widths) as decorative CSS backgrounds. All six icons are stored under `public/figma/account-{bell,user,profile,help,language,logout}.svg`. The older exported chevron assets remain available for existing references. The user's avatar remains supplied dynamically rather than copying the sample portrait. Ant Design owns dropdown/keyboard behavior. Tokens live in `components/ThemeProvider/GlobalStyle/global.ts`; the earlier footer glow adjustment is preserved.

The root layout places the existing `GlobalProvider` inside `<body>`. This preserves the providers and content while preventing their generated wrapper elements from creating invalid HTML directly inside `<html>` and causing hydration failures.
