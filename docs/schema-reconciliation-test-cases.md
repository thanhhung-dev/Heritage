# Schema Reconciliation Test Cases

Scope: Compare the current `schema.sql` against historical Alembic baseline `b6e199de17dd`, recovered unchanged from Git commit `dfb40a2a875fb911e3252dce70cd8cf75f4f428a`.

Execution: 2026-10-29, Asia/Ho_Chi_Minh (UTC+07:00), on an isolated PostgreSQL 17.9 instance with two fresh UTF-8 databases. SQLAlchemy 2.0.54, Alembic 1.20.1, and psycopg 3.3.6 were used. The temporary Alembic environment contained only the baseline revision, so its `head` was `b6e199de17dd`; later historical migrations and current application startup initialization were not tested. The current repository still has no runnable revision chain. No application schema or existing database was modified.

Summary: **5 Pass, 14 Fail, 1 Blocked**. Pass applies only to the recorded scope, not every table/model or all steps of a broader test specification. Catalog comparisons in TC04–TC09, TC13, and TC16 cover shared tables/columns; missing tables are reported in TC03. TC08 checks primary-key column definitions on shared tables, with one duplicate-key probe; TC10, TC14, and TC20 are explicitly scoped runtime samples. TC13 found a conclusive UNIQUE mismatch before testing composite-key partial matches. TC19 is partially executed and remains Blocked because the historical baseline has no seeds.

Evidence: [JSON results and catalog differences](../.amp/in/artifacts/schema-reconciliation-results.json), [execution log](../.amp/in/artifacts/schema-reconciliation-run.log), and [rerunnable comparison script](../.amp/in/artifacts/run_schema_reconciliation.py). These evidence files are local, Git-excluded artifacts. An initial setup run used SQL_ASCII and failed in the runner's text decoding; it was discarded, not counted as a schema failure, and rerun with UTF-8 databases. Both temporary test databases were removed after execution.
